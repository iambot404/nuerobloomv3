Yes. What you want is a **public-first architecture**, where authentication is optional rather than being the entry point.

The flow should be:

```text
                    ┌─────────────────┐
                    │   DocHub Home   │
                    │   /             │
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              ↓              ↓              ↓
         Take Test       Login/Signup    About/Info
              │              │
              │              ↓
              │         Profile
              │              │
              │              ↓
              │          Dashboard
              │
              ↓
       Assessment List
              │
              ↓
        Take Assessment
              │
       ┌──────┴──────┐
       │             │
   Guest User    Logged User
       │             │
       ↓             ↓
 Temporary       Save Progress
 Progress        to Account
       │             │
       ↓             ↓
 Result          Result + History
```

### The key behavior

**Guest:**

`Home → Take Test → Assessment → Result`

No account required.

But:

> Guest progress is temporary and should not be stored permanently.

So if they close the browser, their progress can disappear.

**Logged-in user:**

`Home → Login → Profile → Dashboard`

But they should also be able to go directly:

`Home → Assessments → Assessment → ...`

The important part is that **the authentication state follows the user throughout the application**.

## The important part: Assessment route

Don't make two completely separate assessment systems.

For example:

```text
/assessments
/assessment/<id>
/assessment/<id>/result
```

These routes should detect whether the user is authenticated.

### Guest

```text
GET /assessments

user = not logged in

→ show assessments
→ allow test
→ keep answers/progress in session/localStorage
→ don't write permanent progress to database
```

### Logged in

```text
GET /assessments

user = logged in

→ show assessments
→ load user's existing progress
→ show completed/in-progress assessments
→ save progress to database
```

# One more important distinction

I'd use three states:

```text
                 USER
                  │
        ┌─────────┴─────────┐
        │                   │
      Guest              Logged in
        │                   │
        ↓                   ↓
 Temporary state       Database state
        │                   │
        ↓                   ↓
   localStorage          User ID
```

For guest users:

```javascript
localStorage
```

can hold something like:

```json
{
  "assessmentId": "dysgraphia",
  "currentQuestion": 7,
  "answers": {
    "1": "A",
    "2": "C",
    "3": "B"
  }
}
```

For authenticated users, the same information should be associated with their account in your database.

That gives you exactly what you're describing:

> **The user can enter from Profile → Assessment, Navbar → Assessment, or Take Test, and DocHub knows whether to load their saved progress or create a temporary guest session.**

And I would make **"Take Test" the prominent CTA on the public homepage**, while **Login/Signup are secondary actions**.
